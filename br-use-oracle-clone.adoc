= Clona cargas de trabajo de Oracle Database con NetApp Backup and Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Utiliza NetApp Backup and Recovery para crear clones modificables de cargas de trabajo de Oracle Database a partir de sistemas ONTAP locales en almacenamiento principal o secundario. También puedes programar actualizaciones de los clones para adaptarlas a tus necesidades.

*Rol de NetApp Console requerido* rol de superadministrador de Backup and Recovery o rol de administrador de clones de Backup and Recovery. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["Obtenga información sobre los roles de acceso a la NetApp Console para todos los servicios"^].



[[create-a-clone-of-an-oracle-database]]
== Crear un clon de una base de datos Oracle

Crea un clon inmediatamente a partir de una instantánea existente. Usa este método para crear un clon único que no se actualiza continuamente a partir de una instantánea.

.Pasos
. Desde el menú de la NetApp Console , seleccione *Protección > Copia de seguridad y recuperación*.
. En *Cargas de trabajo*, seleccione el mosaico *Oracle*.
. Selecciona *Clonar*.
. Seleccione *Crear nuevo clon*.
. En la sección *Fuente de la base de datos*, elige el host y la base de datos de origen de las listas.
+
.. Si la base de datos de origen es una base de datos contenedora (CDB), en la sección *Tipo de clon* selecciona una de las siguientes:
+
*** *Clonación completa de la base de datos*: Clona toda la base de datos del contenedor, incluidos todos los PDB.
*** *Clon de PDB*: Clona una PDB específica del backup de la base de datos del contenedor en una base de datos del contenedor de destino ya existente.




. En la sección *Database target*, elige el host y la base de datos de destino de las listas. El host y la base de datos de destino pueden ser diferentes del origen.
. Seleccione *Siguiente*.
. En la sección *Clonar desde* de la página *Seleccionar punto de restauración*, selecciona *Instantáneas existentes*.
. Elige una instantánea existente (punto de restauración) de la lista para usarla como base para el clon y selecciona *Siguiente*.
+
La página *Seleccionar ubicación de la instantánea* aparece si la instantánea está almacenada en más de una ubicación.

. Elige la ubicación de la instantánea que quieres usar y selecciona *Siguiente*.
. En la página *Opciones avanzadas*, haz lo siguiente:
+
.. Opcionalmente, si vas a clonar una base de datos multitenant completa, en *Configuración de clonación completa de la base de datos*, selecciona una o varias PDB para excluir de la clonación (PDB$SEED siempre queda excluida). Esta sección no aparece cuando clonas una base de datos de un solo tenant.
.. Si ya has guardado un archivo de especificaciones, puedes activar la opción *Personalizar parámetros de la base de datos de destino* para cargarlo y personalizar la configuración de la base de datos clonada. También puedes descargar el archivo de especificaciones predeterminado para la instantánea de la base de datos.
.. En la sección *Ámbito de recuperación*, selecciona una opción para recuperar el clon utilizando los registros de archivo e introduce los datos necesarios. Elegir *Ninguna* omite la recuperación (el clon se crea a partir de la instantánea sin aplicar los cambios de los registros de archivo). *Ninguna* no está disponible para los clones de PDB.
.. En la sección *Prescripts and postscripts*, activa una o ambas opciones *Prescript* y *Postscript* para ejecutar un script antes de que comience la operación de clonación o después de que termine. Para cada opción, ingresa la ruta completa del script y cualquier argumento necesario.


. Selecciona *Clonar*.




[[schedule-a-clone-of-an-oracle-database]]
== Programa un clon de una base de datos Oracle

Crea un clon instantáneo y programa actualizaciones periódicas para mantenerlo al día con el estado más reciente de la base de datos.


NOTE: La creación de una instantánea y un clon instantáneos con una programación de actualización solo se aplica a los clones completos de la base de datos. No está disponible para un clon de PDB.

.Pasos
. Desde el menú de la NetApp Console , seleccione *Protección > Copia de seguridad y recuperación*.
. En *Cargas de trabajo*, seleccione el mosaico *Oracle*.
. Selecciona *Clonar*.
. Seleccione *Crear nuevo clon*.
. En la sección *Fuente de la base de datos*, elige el host y la base de datos de origen de las listas.
. En la sección *Database target*, elige el host y la base de datos de destino de las listas. El host y la base de datos de destino pueden ser diferentes del origen.
. Seleccione *Siguiente*.
. En la sección *Clone from* de la página *Select restore point*, selecciona *Instant snapshot and clone*.
. Elige una ubicación para almacenar la instantánea cuando se cree.
. Seleccione *Siguiente*.
. En la página *Opciones avanzadas*, haz lo siguiente:
+
.. Para personalizar la configuración de la base de datos clonada, activa la opción *Personalizar parámetros de la base de datos de destino*. Si antes guardaste un archivo de especificaciones, esta opción te permite subirlo para personalizar la configuración de la base de datos clonada. También puedes descargar el archivo de especificaciones predeterminado para la base de datos que refleja su configuración actual.
.. En la sección *Programación de actualización del clon*, elige cuándo y con qué frecuencia se actualiza el clon. La actualización actualiza la instantánea instantánea y sobrescribe el clon existente con una copia nueva.
.. En la sección *Prescripts and postscripts*, activa una o ambas opciones *Prescript* y *Postscript* para ejecutar un script antes de que comience la operación de clonación o después de que termine. Para cada opción, ingresa la ruta completa del script y cualquier argumento necesario.


. Selecciona *Clonar*.




[[split-a-clone]]
== Dividir un clon

Puedes dividir un clon de tus cargas de trabajo de Oracle Database para crear una copia independiente o a largo plazo. Al dividir un clon, se crea una nueva copia de backup que puede utilizarse para operaciones de protección y restauración.

La operación de división muestra los agregados que forman parte de la máquina virtual de almacenamiento, sus tamaños y la ubicación del volumen clonado. NetApp Backup and Recovery indica si hay espacio suficiente disponible para completar la división. Tras la división, el clon pasa a ser independiente. La tarea de clonación original sigue disponible para operaciones futuras.

.Pasos
. Desde el menú NetApp Backup and Recovery , seleccione *Clonar*.
. Seleccione un clon.
. Seleccione el icono Accionesimage:../media/icon-action.png["Opción de acciones"] > *Clon dividido*.
. Revise los detalles del clon dividido y seleccione *Dividir*.
. Cuando se crea el clon dividido, puedes verlo en la página *Inventario*.




[[delete-a-clone]]
== Eliminar un clon

Elimina los clones de tus cargas de trabajo de Oracle Database para liberar espacio de almacenamiento. Si una política protege el clon, se eliminan tanto el clon como su tarea asociada.

.Pasos
. Desde el menú NetApp Backup and Recovery , seleccione *Clonar*.
. Seleccione un clon.
. Seleccione el icono Accionesimage:../media/icon-action.png["Opción de acciones"] > *Eliminar clon*.
. En el cuadro de diálogo de confirmación de la eliminación del clon, revisa los detalles de la eliminación.
+
.. Para eliminar los recursos clonados de SnapCenter incluso si los clones o su almacenamiento no son accesibles, seleccione *Forzar eliminación*.
.. Seleccione *Eliminar*.


. Cuando se elimina el clon, se elimina de la página *Inventario*.
