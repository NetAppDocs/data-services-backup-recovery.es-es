= Restaura cargas de trabajo de bases de datos Oracle con NetApp Backup and Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Restaura cargas de trabajo de bases de datos Oracle desde instantáneas, backups replicados en almacenamiento secundario o backups almacenados en un almacén de objetos usando NetApp Backup and Recovery.

.Restaurar desde estas ubicaciones
Puede restaurar bases de datos desde diferentes ubicaciones de inicio:

* Restaurar desde una ubicación principal (instantánea local)
* Restaurar desde un recurso replicado en un almacenamiento secundario
* Restaurar desde una copia de seguridad de almacenamiento de objetos


.Restaurar a estos puntos
Puedes restaurar una base de datos en su ubicación original o restaurarla como una nueva base de datos en un host registrado diferente (ubicación alternativa).

* Restaurar a la ubicación original
* Restaurar en una ubicación alternativa (un host registrado diferente)




[[how-oracle-database-restore-works]]
== Cómo funciona la restauración de Oracle Database

Al restaurar cargas de trabajo de Oracle Database, ocurre lo siguiente:

* Cuando restaura una base de datos desde una instantánea local, NetApp Backup and Recovery crea un _nuevo_ recurso utilizando los datos de la copia de seguridad.
* Al restaurar desde un almacenamiento replicado, puede restaurarlo a la ubicación original.
* Al restaurar en una ubicación alternativa, NetApp Backup and Recovery restaura la copia de seguridad seleccionada de la base de datos de origen como una nueva base de datos en un host registrado diferente. Debes especificar el host de destino y un nombre para la nueva base de datos. Si no proporcionas un archivo de especificaciones de restauración, Backup and Recovery calcula automáticamente las ubicaciones de los archivos de datos, los archivos de control y los archivos de registro de recuperación en el host de destino.
* Cuando restaura una copia de seguridad desde el almacenamiento de objetos, puede restaurar los datos en el almacenamiento de origen o en un sistema ONTAP local y recuperar la base de datos desde allí.




[[view-information-about-available-oracle-database-restore-points]]
== Ver información sobre los puntos de restauración disponibles de Oracle Database

Consulta los puntos de restauración disponibles, incluido el número SCN y la encarnación de la base de datos asociada.


NOTE: Oracle Database crea una nueva encarnación de la base de datos cada vez que abres una base de datos con la opción  `RESETLOGS`. NetApp Backup and Recovery enumera las encarnaciones pertinentes de la base de datos cuando revisas los puntos de restauración y cuando restauras a un SCN específico.

.Pasos
. En el menú Backup and Recovery, selecciona *Inventario*.
. Desde el menú de NetApp Backup and Recovery , seleccione *Restaurar*.
. Selecciona *View* para la carga de trabajo de Oracle Database.
. Seleccione la pestaña *Bases de datos*.
. Selecciona el icono *Actions* image:icon-action.png["Icono de acciones"] de una base de datos cuyos puntos de restauración quieras ver y selecciona *View protection details*.
. Revisa los puntos de restauración disponibles, así como el número SCN y la encarnación de la base de datos asociados a cada uno de ellos.




[[restore-an-oracle-database]]
== Restaurar una base de datos Oracle

En función de tus necesidades, puedes restaurar una base de datos Oracle a un momento específico, a un número de cambio del sistema (SCN) específico o al último estado válido. También puedes restaurar la base de datos a partir de instantáneas y omitir el proceso de recuperación automático, por ejemplo, si quieres realizar la recuperación manualmente. Puedes buscar la base de datos usando su nombre o con filtros específicos.

*Rol requerido de NetApp Console*: superadministrador de NetApp Backup and Recovery o administrador de restauración de NetApp Backup and Recovery. https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["Obtenga información sobre los roles de acceso a la NetApp Console para todos los servicios"^].

[[alternate-location-support]]
.Antes de empezar
Cuando realices una restauración en una ubicación alternativa, ten en cuenta los siguientes casos de restauración compatibles y no compatibles:

*Escenarios de restauración en ubicaciones alternativas compatibles*

* Restaurar una sola base de datos Oracle completa en un solo host de destino
* Recuperación a un momento específico, a un SCN específico o a la última copia de seguridad
* Uso de directorios externos de registros de archivo cuando los registros de archivo necesarios para el punto de recuperación seleccionado no están incluidos en la copia de seguridad


*Casos de restauración en ubicaciones alternativas no compatibles*

* Restauración exclusiva de espacios de tabla, incluida la restauración de espacios de tabla dentro de una PDB
* Restauración solo de PDB en una base de datos contenedora (CDB) diferente
* Restaurar desde almacenamiento secundario
* Restaurar desde el almacenamiento de objetos


[NOTE]
====
Si restauras PDB o espacios de tabla a un momento específico o a un SCN:

* Selecciona solo un PDB. La recuperación a un momento específico no es compatible con restaurar varios PDB.
* `PDB$SEED` No se puede seleccionar para recuperación a un momento específico.
* La restauración de archivos de control no se puede combinar con la recuperación a un momento específico de los PDB o de los espacios de tabla de los PDB.
* Los espacios de tabla  `SYSTEM`,  `SYSAUX` y  `UNDO` no se pueden seleccionar.


====
*Notas importantes sobre la restauración de bases de datos de Oracle Data Guard*

* Antes de restaurar, asegúrate de que el rol de la base de datos esté actualizado. Si se produjo una conmutación de sitios o una conmutación por error, selecciona la pestaña *Hosts* y primero selecciona *Refresh* para el host. Las opciones de restauración disponibles dependen del rol que tenga ahora la base de datos.
* Si la base de datos está actualmente en standby, no puedes restaurarla en la ubicación original, independientemente de la función que tuviera cuando se realizó la copia de seguridad. Restáurala en una ubicación alternativa.
* Si la base de datos está actualmente en espera, no puedes restaurar una instantánea que solo exista en almacenamiento secundario o en almacenamiento de objetos.
* Puedes restaurar una copia de seguridad realizada mientras la base de datos estaba en espera en la ubicación original una vez que la base de datos pase a ser la principal.



CAUTION: Restaurar una base de datos primaria no cambia la base de datos en espera. Cuando abres la base de datos primaria con `RESETLOGS` después de una restauración a un momento específico o por SCN, se inicia una nueva encarnación de la base de datos. Si la base de datos en espera ya aplicó el redo más allá de ese punto, la aplicación de redo en la base de datos en espera se detiene con un error y la base de datos en espera permanece en su estado anterior. Para reanudar la protección, vuelve a establecer la base de datos en espera después de la restauración con las herramientas de Oracle.

.Pasos
. Desde el menú de la NetApp Console , seleccione *Protección > Copia de seguridad y recuperación*.
. Desde el menú de NetApp Backup and Recovery , seleccione *Restaurar*.
. En la lista desplegable a la derecha del campo de búsqueda de nombre, seleccione *Oracle*.
. Ingrese el nombre de la base de datos que desea restaurar o filtre por el host de la base de datos donde se encuentra la base de datos que desea restaurar.
+
Aparecerá una lista de instantáneas que coinciden con sus criterios de búsqueda.

. Seleccione el botón *Restaurar* para la base de datos que desea restaurar.
. Elija una opción de restauración:
+
[role="tabbed-block"]
====
.Restaurar a un punto específico en el tiempo
--
.. Seleccione *Restaurar a un punto específico en el tiempo*.
.. Seleccione *Siguiente*.
.. Elija una fecha del menú desplegable y seleccione *Buscar*.
+
Se muestra la instantánea más cercana a la fecha y hora especificadas.

.. Si la instantánea está almacenada en más de una ubicación, selecciona una ubicación de origen para usar y añade o revisa los detalles de la ubicación.
.. Seleccione *Siguiente*.


--
.Restaurar a un número de cambio de sistema específico (SCN)
--
.. Si quieres, consulta <<Ver información sobre los puntos de restauración disponibles de Oracle Database>> para ver los SCN disponibles y las encarnaciones de base de datos asociadas.
.. Seleccione *Restaurar a un número de cambio de sistema específico (SCN)*.
.. Seleccione *Siguiente*.
.. Ingrese el SCN que se utilizará como punto de restauración y seleccione *Buscar*.
+
Se muestra la instantánea que mejor se ajusta al SCN especificado. Si varias encarnaciones de la base de datos coinciden con el SCN, se muestran todas las encarnaciones coincidentes.

.. Si hay varias encarnaciones de la base de datos que coinciden con la búsqueda, selecciona la instantánea con la encarnación correcta.
.. Si la instantánea está almacenada en más de una ubicación, selecciona una ubicación de origen para usar y añade o revisa los detalles de la ubicación.
.. Seleccione *Siguiente*.


--
.Restaurar a la última copia de seguridad (último estado correcto)
--
.. Seleccione *Restaurar a la última copia de seguridad*.
.. Seleccione *Siguiente*.
+
Se muestra la última instantánea. La operación de restauración recupera el último estado válido usando todos los backups de registro disponibles.

.. Si la instantánea está almacenada en más de una ubicación, selecciona una ubicación de origen para usar y añade o revisa los detalles de la ubicación.
.. Seleccione *Siguiente*.


--
.Restaurar desde instantáneas sin recuperación
--
.. Seleccione *Restaurar desde instantáneas sin recuperación*.
+
Al seleccionar esta opción, la base de datos se restaurará a partir de instantáneas, pero se omitirá la recuperación (no se aplicarán los backups de registros).

.. Seleccione *Siguiente*.
+
Se muestran las instantáneas disponibles.

.. Selecciona una instantánea de la lista y selecciona *Siguiente*.
.. Si la instantánea está almacenada en más de una ubicación, selecciona una ubicación de origen para usar y añade o revisa los detalles de la ubicación.
.. Seleccione *Siguiente*.


--
====
. Elija el destino de restauración y la configuración:
+
[role="tabbed-block"]
====
.Restaurar a la ubicación original
--
.. En la sección *Configuración de destino*, haz lo siguiente:
+
... En el caso de las bases de datos RAC, selecciona el nodo RAC en el que se va a ejecutar la restauración. Esta opción solo aparece para las bases de datos RAC.
... Selecciona lo que quieres restaurar:
+
**** Selecciona *Todos los archivos de datos* para restaurar toda la base de datos o la base de datos contenedora (CDB).
**** Selecciona *Bases de datos conectables (PDBs)* para restaurar una o varias PDBs desde una CDB sin afectar a las demás PDBs del contenedor. Luego selecciona las PDBs de la lista.
**** Selecciona *Espacios de tabla de base de datos conectables (PDB)* (que aparecen como *Espacios de tabla* en una base de datos que no sea CDB) para restaurar espacios de tabla PDB específicos. Luego, selecciona la PDB y los espacios de tabla.


... Si lo deseas, activa la opción *Archivos de control* para restaurar también los archivos de control de la base de datos. Esta opción no se puede seleccionar para la recuperación a un momento específico o por SCN de PDB o espacios de tabla de PDB.
... Si lo deseas, activa la opción *Cambiar el estado de la base de datos si es necesario para la restauración y la recuperación* para permitir que NetApp Backup and Recovery gestione el estado de la base de datos según el tipo de recuperación.
... Si lo deseas, activa la opción *Force in place restore* para restaurar sin movimiento cuando se hayan añadido nuevos archivos de datos después de la copia de seguridad, o cuando se hayan añadido, eliminado o vuelto a crear LUN en un grupo de discos LVM. Esto anula la comprobación de archivos externos; la recuperación de bases de datos continúa usando la opción de restauración que hayas seleccionado.
... Especifica las ubicaciones de los archivos de registro de archivo externos en el campo *Especificar ubicaciones de los archivos de registro de archivo externos* si vas a restaurar una base de datos a un momento específico o a un SCN, y los archivos de registro de archivo no están en la ubicación configurada. Introduce una ruta del sistema de archivos que empiece por `/` o un grupo de discos ASM que empiece por `+`. Usa los botones «más» y «menos» junto al campo de entrada de texto para añadir o quitar ubicaciones. Este campo no aparece cuando restauras desde snapshots sin recuperación.
... Si lo deseas, activa la opción *Abrir la base de datos o la base de datos contenedora en modo lectura/escritura tras la recuperación* y selecciona una subopción que se ajuste al ámbito de la restauración (estas opciones no aparecen cuando se restaura a partir de instantáneas sin recuperación):
+
**** *Todos los archivos de datos*: Abre la base de datos o la base de datos contenedora en modo lectura/escritura tras la recuperación.
**** *PDB o espacios de tabla PDB*: Abre las bases de datos conectables en modo lectura/escritura tras la recuperación.
**** *Espacios de tabla que no pertenecen al CDB*: Pon los espacios de tabla en línea después de la recuperación.




.. En la sección *Prescripts y postscripts*, haz lo siguiente:
+
... *Prescript*: Si lo deseas, activa esta opción e introduce la ruta completa de un script que debe ejecutarse antes de la operación de restauración y cualquier argumento que requiera dicho script.
... *Posdata*: Opcionalmente, habilite esta opción e ingrese la ruta completa de un script que debe ejecutarse después de la operación de restauración y cualquier argumento que tome el script.
... Elige un valor de tiempo de espera para el script. Si el script no se ejecuta dentro de este plazo, la restauración se llevará a cabo de todos modos.

.Restaurar a una ubicación alternativa
--
Restaura una base de datos como una nueva base de datos en un host registrado diferente. Revisa la <<alternate-location-support,escenarios compatibles y no compatibles>> antes de empezar.

.. En la sección *Configuración de destino*, introduce la siguiente información:
+
... *Host de destino*: selecciona el host registrado en el que quieres crear la nueva base de datos.
... *Base de datos de destino*: introduce un nombre para la base de datos de destino. Por defecto, el nombre comienza con el nombre de la base de datos de origen y puedes modificarlo.
... *Personalizar los parámetros de la base de datos de destino*: activa esta opción para cargar un archivo de especificaciones de restauración personalizado con el fin de personalizar los parámetros de la base de datos de destino.
... *Archivo de especificaciones de restauración*: si has activado la opción *Personalizar parámetros de la base de datos de destino*, proporciona un archivo de especificaciones de restauración para controlar dónde se colocan los archivos restaurados en el host de destino. Puedes descargar un archivo de especificaciones de restauración predeterminado y personalizarlo para cambiar los detalles de la base de datos de destino, como la autenticación y las ubicaciones de los registros.
+
Si no proporcionas un archivo de especificaciones de restauración, Backup and Recovery calcula automáticamente las ubicaciones de los archivos de datos, los archivos de control y los archivos de registro de recuperación.

... Especifica las ubicaciones de los archivos de registro de archivo externos en el campo *Especificar ubicaciones de los archivos de registro de archivo externos* si vas a restaurar una base de datos a un momento específico o a un SCN, y los archivos de registro de archivo no están en la ubicación configurada. Introduce una ruta del sistema de archivos que empiece por `/` o un grupo de discos ASM que empiece por `+`. Usa los botones «más» y «menos» junto al campo de entrada de texto para añadir o quitar ubicaciones. Este campo no aparece cuando restauras desde snapshots sin recuperación.
... Si lo deseas, activa la opción *Abrir la base de datos o la base de datos contenedora en modo lectura/escritura tras la recuperación* y selecciona una subopción que se ajuste al ámbito de la restauración (estas opciones no aparecen cuando se restaura a partir de instantáneas sin recuperación):




--
====
. Seleccione *Restaurar*.
+
Una vez finalizada la operación de restauración, comprueba la página *Inventario* para confirmar que la nueva base de datos aparece en la lista. Si la base de datos no aparece en la lista, actualiza el host de destino.
